# Lark Gateway 远程操控 README 设计

## 目标

将 `lark-claude/README.md` 现有零散“使用”内容整理成可直接照抄的远程操控速查表，并提供简短故障排查。文档只描述当前已经实现并验证的行为，不扩展 Gateway 功能。

## 结构

保留安装、配置及底层安全说明，重写“使用”区域为以下顺序：

1. `远程操控速查`：说明只能私聊已授权机器人，以及推荐消息结构。
2. `常用操作`：用表格列出新建或续接、明确新建、继续最近会话、查询项目和会话、查询活动 Session、精确停止、批准或拒绝、CC Switch 查询等示例。
3. `候选列表`：说明模糊匹配和工程选择的编号交互；优先使用飞书“回复”功能，同一聊天、同一发送人恰好只有一个已发送、仍打开且未过期的候选列表时，可独立发送 `1` 到 `10`。
4. `执行流程`：用一条短流程描述消息从匹配到入队、执行和结果回传。
5. `故障排查`：覆盖找错会话、编号不生效、多个候选、Session 忙碌或状态变化、审批、Claude 无 Bash、Gateway 不在线。
6. `行为与安全边界`：保留现有自动发现、恢复前复验、项目串行、停止 ID、CC Switch 只读等技术说明，删除与速查表重复或已经过时的表述。

## 示例规则

- 示例优先使用明确形式：`Codex <项目名> <会话名> <任务>` 或 `Claude <项目名> <会话名> <任务>`。
- 项目名只写已配置别名或从原生 `cwd` 发现的目录名，不使用绝对路径。
- 不把 Codex Desktop 侧边栏逻辑分组名描述为自动可用；当前 Gateway 项目身份仍来自验证后的原生 `cwd` 和可选本地别名覆盖。
- “继续或新建”与“明确新建”分开说明；只有明确要求新建时才绕过模糊复用，但仍受名称占用保护。
- 停止示例只接受查询结果中的完整 `ST-` 引用，不使用会话名、PID 或 UUID。
- 审批示例使用完整 `RQ-` 引用。

## 故障排查边界

- “编号不生效”：确认使用飞书回复功能；独立编号只在当前聊天和发送人恰好只有一个已发送、仍打开且未过期的候选列表时工作。
- “多个有效候选列表”：必须回复目标候选消息，Gateway 不按最近时间猜测。
- “找不到项目”：使用目录名或本地配置别名；消息中的路径不会成为执行权限。
- “Session 忙碌/状态变化”：等待本机所有者结束后重新发送完整任务，不会创建同名替代会话。
- “需要批准”：只回复完整批准或拒绝引用；自动批准范围不包含删除、越界写或未知命令。
- “Claude 无法运行 Git”：Gateway 管理的 Claude Worker 当前未启用 Bash。
- “Gateway 无响应”：检查 `npm run status`、`run/health.json` 和 `%LOCALAPPDATA%\lark-claude\gateway.log`。

## 验收

- README 中不再出现“单独发送数字不会选择 Session”。
- 所有命令示例与当前路由字段、候选确认、停止和审批约束一致。
- 新用户只阅读速查表和故障排查即可完成一次续接、一次候选确认和一次状态检查。
- 保留现有配置、安全和实现边界信息，不覆盖工作区中的其他 README 修改。

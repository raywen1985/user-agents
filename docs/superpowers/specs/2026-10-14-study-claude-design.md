# `study-claude` AI 应用学习工程设计

日期：2026-10-14

## 目标

在 `.agents/study-claude/` 创建一个可长期维护的个人 AI 学习工程，并在 `.agents/skills/ai-application-learning/` 创建一个统一入口 Skill。工程服务于一名有 20 年经验、当前从事 Unity 游戏开发、技术管理、架构设计和业务系统开发的程序员，重点关注 AI 在工作、生活和子女教育中的应用赋能。

学习系统同时覆盖系统主题路线和近期前沿动态，以每天约 30 分钟的个人学习为默认单位。亲子学习按需生成，不安排固定日程。

## 非目标

- 不教授或规划 LLM harness、模型训练基础设施、推理服务框架等底层开发路线。
- 不把工程建设成新闻聚合服务、自动爬虫、定时任务或完整学习平台。
- 不替代具体的 Unity 故障排查、普通代码实现或业务项目开发能力。
- 不自动创建提醒、日历事件、外部任务或亲子日程。
- 不收集完成学习设计所不需要的个人或儿童敏感信息。

## 总体方案

采用“一个入口 Skill + 模块化学习工程”的结构。Skill 负责识别意图、选择学习模式、读取相关画像和模板、生成内容并维护连续性；`study-claude` 工程负责保存知识地图、场景资料、来源规则、模板和学习记录。

这种结构对使用者只暴露一个稳定入口，同时避免把路线、分龄规则、来源标准和输出模板全部堆入 `SKILL.md`。第一版不拆分多个专项 Skill，避免触发冲突和重复维护。

`study-claude/` 是学习资料和记录的所有者；`skills/ai-application-learning/` 是多个 Agent 可发现的能力入口。Skill 不根据自身入口路径拼接工程位置，因为 Claude Code 通过 Junction 发现 Skill 时，入口路径与真实目录路径不同。

工程根目录使用以下可测试的定位契约：

1. 若调用方显式提供 `AGENTS_ROOT`，使用该目录。
2. 否则使用运行环境解析出的用户主目录下 `.agents`，例如 Windows 的 `$env:USERPROFILE/.agents`。这是可迁移的主目录相对位置，不在文件中保存某台机器的绝对路径。
3. 验证候选目录同时包含 `study-claude/README.md` 和 `skills/ai-application-learning/SKILL.md`；验证失败时停止读写并报告配置问题，不能猜测其他目录。

该契约需要分别通过 `.agents/skills` 原生入口和 `.claude/skills` Junction 入口验证。若未来允许把仓库放到非默认位置，必须显式设置 `AGENTS_ROOT`。

## README 与 `.gitignore`

`study-claude/README.md` 说明：

1. 工程目标和明确非目标。
2. 使用者背景及三个应用方向。
3. 每日 30 分钟学习流程。
4. 目录职责和学习记录方式。
5. 典型使用示例，如“今天学什么”“解释这个概念”“近期有什么值得关注”“把 AI 用到这个工作问题”。
6. 来源可信度、隐私和儿童使用边界。

`study-claude/.gitignore` 至少忽略 `profiles/*.local.md`、`notes/private/`、`sources/raw/`、`.cache/`、`tmp/`、生成结果和编辑器文件。正式路线、模板、经过脱敏的学习总结和非敏感进度可被 Git 跟踪。规则只作用于该工程，不能影响仓库其他模块。

默认持久化策略是“私密优先”：包含儿童信息、未公开工作内容、公司或项目标识、内部代码、健康财务信息的内容写入被忽略的本地路径，或不落盘。只有不含这些信息的学习总结才能写入可跟踪的 `notes/`。Skill 写入前先做分类和最小化处理；无法确定是否敏感时使用本地私密路径，并告知用户。

## 学习画像

`profiles/learner.md` 记录设计学习内容所需的稳定背景：

- 20 年程序开发经验。
- 当前关注 Unity 游戏开发、技术管理、架构设计和业务系统开发。
- 学习目标是应用赋能，而不是 LLM harness 或底层模型工程。
- 默认每天个人学习 30 分钟。
- 偏好“主题路线 + 前沿动态”的组合。

`profiles/family.example.md` 只提供字段说明和占位值。两个孩子的精确生日写入被 Git 忽略的 `profiles/family.local.md`，不进入规格、模板、示例或提交历史。Skill 从本地日期按当前日期动态计算年龄，不能把某次计算所得年龄永久写死。除非用户主动补充且任务确实需要，不记录姓名、学校、住址、人脸、声音、账号等信息。

## 知识路线

`roadmap/ai-application-roadmap.md` 建立面向资深程序员的应用知识地图，避免重复基础编程教学。第一版包括：

1. 生成式 AI 与主流模型能力边界。
2. 提示、上下文和结构化任务表达。
3. 文本、图像、语音与视频等多模态应用。
4. 检索增强、知识库和个人信息管理的应用视角。
5. Agent 与工作流自动化的使用、选择和风险，不进入 harness 实现。
6. AI 辅助研发、架构分析、技术管理和业务系统工作的实践。
7. AI 输出评测、事实核验、隐私、安全、版权和成本意识。
8. 面向家庭与儿童的 AI 素养、创造性实践和健康使用。

路线按“理解 -> 判断 -> 应用 -> 复盘”组织，不以产品清单替代知识结构。前沿变化只更新具体案例和当前能力判断，不频繁重写稳定概念。

## 应用方向

### 工作赋能

优先覆盖 Unity 游戏开发、技术管理、架构设计和业务系统开发，例如需求澄清、方案比较、代码与资源审查、故障分析、知识沉淀、会议与决策辅助。内容强调人机分工和可验证结果，不把生成速度等同于工程质量。

### 生活应用

覆盖信息整理、消费决策、旅行与家庭规划、个人知识管理和创意辅助。涉及健康、财务、法律或其他高影响判断时，明确 AI 局限、信息时效和人工核验要求。

### 亲子教育

按需为两个孩子生成同主题、不同难度的活动：女儿侧重批判性思考、研究、表达、创作和负责任使用；儿子侧重直观体验、提问、观察、验证和创造。活动不安排固定日程，不鼓励用 AI 代做作业，也不要求上传儿童敏感信息。

## Skill 行为

Skill 名称为 `ai-application-learning`，负责以下四类主要入口：

1. **每日学习**：根据路线和近期记录生成一个约 30 分钟的连续学习单元。
2. **概念学习**：用资深程序员能够快速吸收的方式解释指定 AI 概念，并连接实际应用。
3. **前沿速览**：筛选近期重要进展，说明来源、日期、可信度、实际意义和是否值得投入时间。
4. **问题赋能**：把工作、生活或亲子问题转化为可执行的 AI 应用方案。

默认每日单元分配为：回顾 3 分钟、核心概念 12 分钟、应用案例 8 分钟、前沿动态 4 分钟、复盘与下一步 3 分钟。用户指定主题或时间时可调整，但应维持一次可完成的范围。

Skill 读取最少必要资料：先判断请求类型，再读取对应画像、路线、方向或模板。只有需要延续学习时才读取进度和最近记录，避免每次加载整个工程。生成学习内容后，只有在用户明确说“完成”“学完了”“记录本次”“保存学习记录”或等价表达时才保存；单纯请求或阅读学习内容不算完成，不能写入笔记或推进进度。

## 来源与前沿判断

`sources/source-policy.md` 定义以下规则：

- 前沿内容优先使用官方产品文档、研究论文、模型卡、标准组织和有公开研究方法、作者及原始材料的研究机构一手资料。
- 每份速览声明 `as_of` 日期。“近期”默认指 `as_of` 前 30 个自然日；若不足 3 条真正相关的进展，可扩展到 90 日，但必须显式标注扩展范围。
- 每项时效性结论记录标题、URL、发布或事件日期、访问日期；页面更新日期只有在能确认内容发生实质变化时才可作为新进展日期。
- 区分可验证事实、厂商声明、社区观察和分析判断。
- 二手报道可用于发现线索，但重要结论应回到一手来源。存在争议的结论需要至少两个相互独立的来源且其中至少一个是一手来源，否则标记为“未充分确认”。
- 评估进展时同时说明能力、限制、成熟度、成本、隐私和适用场景，避免追逐名词。
- 无法检索或确认近期资料时，明确说明限制，不编造来源、日期或“最新”结论，并退回稳定主题路线。

## 状态与数据流

一次典型学习请求的数据流为：

1. 识别请求属于每日学习、概念学习、前沿速览或问题赋能。
2. 读取学习者画像和所需方向资料。
3. 每日学习时读取 `state/progress.json`，并用 `last_session_id` 定位最近的正式学习记录；该字段缺失或指向无效记录时，解析有效记录的 frontmatter，选择 `completed_at` 最大的一份，不能依赖文件名排序推断时间。
4. 前沿内容需要时检索并按来源规则筛选；不能确认时显式降级。
5. 用对应模板生成限定时长的内容和实践。
6. 提供简短复盘问题与建议的下一步。
7. 用户明确确认完成或要求保存后，再写入 Markdown 学习记录并幂等更新进度。

学习记录采用 `YYYY-MM-DD-<roadmap-unit>-<slug>.md` 命名，并包含 YAML frontmatter：`session_id`、`completed_at`、`roadmap_unit`、`mode`、`status`、`next_unit`、`privacy` 和 `sources`。`session_id` 使用日期、路线单元和主题组成的稳定标识；重复保存同一 `session_id` 时更新原记录，不创建副本。

`state/progress.json` 使用固定字段：`schema_version`、`current_unit`、`completed_units`、`last_session_id`、`last_completed_at` 和 `next_unit`。只有 `status: completed` 的记录才把当前单元加入 `completed_units` 并推进 `current_unit`；保存草稿或部分完成记录不推进路线。状态更新采用先验证、再写临时文件、最后原子替换的方式；格式异常时停止写入并保留原文件。

学习记录保持为可读的 Markdown，进度使用结构化 JSON；两者都不需要数据库或运行时服务。首版不维护复杂积分、连续打卡或自动排课系统。

## 错误处理与边界

- 缺少学习记录或进度文件时，从画像和路线起点开始，并在首次明确保存时创建状态，不将其视为错误。
- 记录格式异常时保留原文件，说明问题并建议修复，不能静默覆盖。
- 问题范围超过 30 分钟时，拆成一个当次可完成单元和后续候选，不一次输出完整大课。
- 来源冲突时并列呈现差异和日期，不擅自合并成确定事实。
- 请求属于普通代码修复、具体 Unity 故障或 harness 开发时，不触发或继续套用学习流程。
- 涉及儿童、高影响决策或隐私时，给出与风险相称的边界提示和人工核验步骤。

## 验收与评测

### 静态验收

- `study-claude/README.md`、`.gitignore` 和约定目录完整。
- Skill 目录名与 frontmatter `name` 一致，`description` 同时说明触发范围和排除范围。
- Skill 引用的所有路径存在，不包含单机绝对路径，并按根目录定位契约验证标记文件。
- `family.local.md`、`notes/private/` 和原始抓取内容经 `git check-ignore -v` 确认为忽略；跟踪文件中不含精确生日、儿童身份信息或未公开工作内容。
- Markdown 标题、代码围栏和链接结构正确。
- Git 差异不包含凭据、抓取缓存或仓库中其他模块的意外修改。

### 行为评测

`evals/evals.json` 遵循 `skill-creator` 约定的 `skill_name` 和 `evals[]` 结构；每个用例包含唯一整数 `id`、真实 `prompt`、`expected_output` 和可逐条判定的 `expectations`，需要固定输入时使用相对路径 `files`。至少覆盖：

- 生成一个连续、约 30 分钟的主题学习单元。
- 使用固定 `as_of` 和 `frontier-fixture.md` 生成带 URL、发布/事件日期、访问日期、时间窗口及可信度判断的离线前沿速览。
- 把 AI 应用于 Unity 游戏开发或技术管理问题。
- 为同一主题生成适合两个孩子的分龄活动。
- 在明确设定“检索不可用”的固定条件下诚实降级而不编造。
- 普通代码修复、具体 Unity 故障、模型训练基础设施和 LLM harness 开发不应触发。
- 仅生成学习内容时不写文件；明确保存后只新增或更新一份记录并推进一次状态，重复保存保持幂等。
- 从 `.agents/skills` 原生入口和 `.claude/skills` Junction 入口都能定位同一个 `study-claude` 工程。

“约 30 分钟”的可判定代理标准是输出包含各环节分钟数且总和为 30 分钟，核心概念只设一个主题，动手实践不超过一个，复盘问题不超过三个。其他质量检查包括：是否连接已有经验、事实与观点是否区分、时效性内容是否带完整来源元数据、实践是否可执行、亲子内容是否分龄且保护隐私。

实现后必须实际执行代表性行为评测并逐条记录期望是否通过。通过标准为所有安全、隐私、路径定位、保存/不保存和非触发期望 100% 通过，其余期望总体通过率不低于 90%。随后按 `ai-install.md` 同步新增顶层 Skill 链接，并分别在 Codex 原生发现和 Claude Junction 的全新会话中验证 Skill 可发现、工程可读取；不能只检查文件存在。第一版不引入额外运行时、定时自动化或外部服务。

## 成功标准

- 用户能用一个稳定 Skill 入口开始每日学习、查询概念、了解前沿或解决应用问题。
- 默认学习单元适合每日 30 分钟，并能通过正式笔记保持连续性。
- 工作内容明显贴合 Unity、技术管理、架构设计和业务系统开发，而非面向初学程序员的泛化教程。
- 前沿信息有来源意识和时间意识，不以营销热度替代判断。
- 亲子内容能根据生日动态分龄，且不安排日程、不代做作业、不索取敏感信息。
- 工程边界清晰，不滑向 LLM harness 或底层模型基础设施开发。

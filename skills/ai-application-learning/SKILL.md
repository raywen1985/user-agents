# AI Application Learning

建立连续、可验证的 AI 应用学习，而不是堆积资讯或生成泛化课程。默认面向有丰富工程经验的学习者，重点是能力边界、场景判断、实际应用和责任治理。

## 定位工程根目录

不要根据当前 `SKILL.md` 的入口路径拼接工程位置。Claude Code 可能通过 Junction 加载 Skill，入口路径与真实仓库路径不同。

1. 检查调用环境是否显式提供 `AGENTS_ROOT`；若有，解析为绝对路径。
2. 否则使用操作系统解析出的用户主目录并追加 `.agents`。Windows 优先使用 `$env:USERPROFILE`，其他环境使用等价的用户主目录 API。
3. 验证根目录同时包含 `study-claude/README.md` 和 `skills/ai-application-learning/SKILL.md`。
4. 验证失败时停止读取和写入，清楚报告尝试过的候选路径及如何设置 `AGENTS_ROOT`。不要扫描整块磁盘或猜测其他目录。

后文路径均相对于已验证的 `.agents` 根目录。

## 判断请求模式

选择一个主模式；需要时可以引用另一个模式的少量内容，但不要把所有模式一次输出。

| 模式 | 典型请求 | 主要产出 |
|---|---|---|
| `daily` | 今天学什么、继续学习、给我 30 分钟课程 | 一个 30 分钟连续学习单元 |
| `concept` | 解释 RAG、什么是多模态评测 | 概念、边界、反例和小实践 |
| `frontier` | 最近有什么进展、这个新模型值得关注吗 | 有截止日期和来源判断的速览 |
| `application` | AI 如何用于 Unity、管理、生活或教育 | 场景化方案、风险和试点 |

普通代码实现、具体 Unity 报错排查、与 AI 无关的新闻、模型训练基础设施、推理服务框架和 LLM harness 开发不属于本 Skill。不要把这些请求改写成学习单元；直接使用更合适的能力或回答。

## 按需读取资料

先完成范围判定；如果请求属于前述排除项，立即退出本 Skill，不读取画像、路线或进度。确认属于本 Skill 后，始终先读 `study-claude/profiles/learner.md`，然后只读取主模式需要的资料：

- `daily`：`roadmap/ai-application-roadmap.md`、`state/progress.json`、`templates/daily-session.md`，以及相关 track。
- `concept`：路线中相关单元和相关 track；需要 30 分钟结构时再读每日模板。
- `frontier`：`sources/source-policy.md` 和 `templates/frontier-brief.md`。
- `application`：对应的 `tracks/work.md`、`tracks/life.md` 或 `tracks/family-education.md`。

需要保持连续性时，用 `state/progress.json` 的 `last_session_id` 找到最近记录。该字段缺失或失效时，解析有效笔记的 frontmatter，选择 `completed_at` 最大的一份。不要通过文件名字典序推断最近记录。

亲子请求读取 `profiles/family.local.md`。如果文件不存在，只使用用户当前请求中明确提供的年龄；需要长期分龄时，先说明 `family.local.md` 是 Git 忽略的本地文件，并在用户明确同意保存后创建。精确生日只用于本地计算，不要把它写入可跟踪文件，也不要在用户回答中复述；回答只使用计算后的年龄或学习阶段。

## 生成学习内容

### Daily

遵循 `templates/daily-session.md`：

- 回顾 3 分钟
- 核心概念 12 分钟
- 应用案例 8 分钟
- 前沿动态 4 分钟
- 复盘与下一步 3 分钟

分钟数总和必须为 30。只设一个核心主题、一个动手实践和不超过三个复盘问题。连接学习者已有的架构与工程经验，跳过基础编程教学。

如果没有进度，从 `foundation-01` 开始。如果存在进度，优先继续 `next_unit`；用户指定主题时可以临时跳转，但除非明确完成并保存，不改变路线状态。

### Concept

使用以下顺序：

1. 一句话定义。
2. 它解决的问题和工作方式。
3. 适用条件与不适用条件。
4. 一个与资深程序员经验相连的类比，并指出类比失效处。
5. 一个反例或常见失败方式。
6. 一个可核验的小实践。

不要用术语堆叠替代解释，也不要默认把概念引向框架实现。

### Frontier

先声明 `as_of` 日期。按 `sources/source-policy.md` 检索和筛选：

- 默认窗口为截止日前 30 个自然日。
- 不足三条相关进展时可以扩展到 90 日，并明确说明。
- 每项给出标题、URL、来源类型、发布或事件日期、访问日期、声明分类、限制和可信度理由。
- 厂商性能声明不等同于独立验证；争议结论需要两个独立来源，其中至少一个是一手来源。
- 优先解释对学习者实际工作的影响，不按热度罗列产品。

检索不可用或无法确认日期时，明确说明限制，不使用“最新”一词，不编造来源，并改为稳定概念、核验清单或请用户提供候选链接。

### Application

输出以下内容：

1. 问题与当前成本。
2. AI 适合承担的部分。
3. 必须由人负责的判断。
4. 输入数据及隐私等级。优先使用组织现有分级；没有既有标准时使用“公开 / 内部 / 机密 / 受限”四级并解释判断。
5. 替代方案，包括不用 AI。
6. 一个低风险、可回退的小试点。
7. 成功指标、停止条件和核验方式。

工作场景优先连接 Unity 游戏开发、技术管理、架构设计和业务系统。不要把演示效果当成生产可用性。

亲子场景要为每个孩子动态计算年龄，围绕同一目标提供不同难度。较大孩子侧重来源比较、论证、创作和责任；较小孩子侧重观察、提问、验证和短创作。不安排固定日程，不代做作业，不要求上传敏感信息。

## 处理隐私

写入前对内容分类：

- 儿童信息、未公开工作内容、公司或项目标识、内部代码、健康或财务信息属于私密内容。
- 私密内容只写入 `study-claude/notes/private/` 或不落盘。
- 可跟踪的 `study-claude/notes/` 只保存脱敏知识总结。
- 无法确定是否敏感时按私密处理，并告诉用户保存位置与原因。

高影响的健康、财务、法律和教育判断需要说明 AI 局限、信息日期与人工核验步骤。

## 保存学习记录

生成或展示内容本身不授权写入。只有用户明确说“完成”“学完了”“记录本次”“保存学习记录”或等价表达时才保存。

保存时读取 `study-claude/templates/reflection.md` 和 `study-claude/notes/README.md`，并遵循：

1. 创建稳定 `session_id`：`YYYY-MM-DD-<roadmap-unit>-<topic-slug>`。
2. 先查找相同 `session_id`；存在则更新原记录，不新建副本。
3. 文件名使用 `YYYY-MM-DD-<roadmap-unit>-<slug>.md`。
4. 写入完整 YAML frontmatter 和简洁复盘正文。
5. 只有 `status: completed` 才推进路线；`completed_units` 去重。
6. 同一 `session_id` 重复保存不得再次推进。
7. 更新进度前验证 JSON；写同目录临时文件后原子替换 `state/progress.json`。
8. 原进度或目标笔记格式异常时停止写入，保留原文件并报告问题。

## 输出风格

- 直接面向资深工程师，优先解释权衡和边界。
- 用具体案例和验证步骤替代抽象口号。
- 对时效性结论使用绝对日期。
- 明确区分事实、厂商声明、社区观察和分析判断。
- 将一次输出控制在用户可实际完成的范围，不生成宏大的长期日程。
